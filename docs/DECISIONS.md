# Decisions

Defaults chosen during the autonomous build, with the reason for each.

## Tooling
- **Flat package layout** (`escalate/` at the repo root, not `src/`), matching CLAUDE.md. Built with
  `uv_build` (`module-root = ""`) so `uv sync` installs the package editable and `ui/app.py` can
  import it.
- **`cryptography` pinned to 46.0.3 on Intel macOS only.** Newer releases ship no x86_64 macOS
  wheel and fail to build without OpenSSL headers. All other platforms (Linux, Docker, CI, Apple
  Silicon) get the current release via a platform marker.
- **`python-multipart`** added: FastAPI needs it for the multipart evidence upload endpoint.
- **`types-PyYAML`, `types-jsonschema`** added as dev deps so mypy can check YAML/schema code.
- CI also runs `ruff format --check` (listed in CLAUDE.md's lint command) and installs Pango so
  WeasyPrint can render PDFs.

## Database (task 1.2)
- `Case.country` and `Case.currency` are **nullable**: a case is created from free text before
  classification, and CLAUDE.md forbids country/currency defaults. `classify` fills them.
- Extra columns beyond section 5: `Case.description` (user's own words), `Evidence.filename`,
  `Evidence.ocr_confidence`, `Evidence.needs_review` (task 1.4), `Message.rejection_reason`,
  `Message.external_id` (Gmail message id), `Message.created_at`. Message status adds `rejected`.
- `amount` is `Decimal` (not float) to avoid rounding money.
- Foreign keys use `ON DELETE CASCADE` and SQLite `PRAGMA foreign_keys=ON`, so deletes cascade
  both via the ORM and at SQL level.
- Timestamps are naive UTC via `escalate.db.models.utcnow()` (works with freezegun).

## LLM (task 1.3)
- Code gets the model through `escalate.llm.get_llm()`; tests install `FakeLLM` with `set_llm()`.
  Services also accept an explicit `llm` argument.
- The OpenAI SDK's own retries are off (`max_retries=0`); `LLMClient` retries HTTP 429 with
  exponential backoff (1s, 2s, 4s, … up to 5 retries). The sleep function is injectable for tests.
- `MODEL_FAST` falls back to `MODEL_SMART` when blank. A placeholder like `<local-instruct-model>`
  raises a clear "set MODEL_SMART" error instead of a confusing 404.
- `is_cloud()` treats `localhost`, `127.0.0.1`, `::1`, `ollama` (the compose service),
  `host.docker.internal` and `*.local` as local.

## Evidence (task 1.4)
- `save_upload(session, case_id, filename, data)` takes the DB session explicitly and extracts
  text immediately, so the stored row already has `extracted_text`.
- Images with no Tesseract installed, unreadable files, scanned PDFs with no text layer, and
  unknown file types are stored but flagged `needs_review=True` (the user types the details).
  No vision-model fallback in v0.1 (section 9 says optional); no cloud call is ever made here.
- Fixtures are generated by `tests/fixtures/make_fixtures.py` (PDF written by hand, no new dep).

## Playbooks (task 1.5)
- **Regions are ISO 3166-2 codes** (`PK-SD`, `PK-PB`, `PK-KP`, `PK-IS`), not the
  `sindh, punjab, kp, ict` names in the section 6 example, per CLAUDE.md rule 4.
- The generic fallback uses `country: INTL` and `generic: true`.
- **Template refs** like `pk/legal_notice_15_day.md.j2` resolve to
  `templates/pk/<language>/legal_notice_15_day.md.j2`, falling back to `en`.
- **`currency` is a required fact** in every money-related playbook (section 6's example omits
  it), so amounts render with Babel in the right currency.
- **`buyer_name` means "the consumer"** in every playbook (refund, subscription and scam) so
  extraction and templates share one key.
- Schema additions beyond section 6: step `name`, `recipient_role`, `recipient_fact` (which fact
  holds the address), `requires` (extra facts a step needs, asked before drafting),
  `on_partial`; deadline `days`, `from_fact`, `from_step`; playbook `sector`, `company`, `generic`;
  source `note`. `when` supports only `"<fact> is set"` / `"<fact> is not set"`.
- **Resolver ranking:** company (same country, then INTL) > region match > country-wide >
  region-specific playbook when the user's region is unknown > intl/generic. A region-specific
  playbook is skipped when the user's region is known and not listed.
- **The validator also fails when a template uses a variable that is not a playbook fact**
  (rule 2, "facts only"). Allowed extra context: `today`, `reply_by`, `language`, `generic`,
  `case_ref`, `late`.
- **No unverified URLs.** The generic playbooks cite "your national consumer authority / your
  bank's fraud line" with no URL; candidate international URLs could not be verified during the
  build, so none were added. The validator warns on URL-less sources in non-generic packs.
- `PK` court filing deadline: `from_fact: cause_of_action_on` if the user knows it, otherwise
  the clock starts when the 15-day notice period ends. This interpretation needs lawyer review.

## Intake and evals (task 1.6)
- Prompt files use `{name}` placeholders replaced by `render_prompt()`; other braces (the JSON
  shapes in the prompts) are left alone, so prompts stay copy-paste readable.
- The extraction prompt also lists the playbook's **optional** keys so useful extras
  (return date, tracking number) are captured. Keys outside required+optional are discarded.
- Facts with confidence < 0.5, empty values, and evidence ids that were not provided are never
  stored. A user's typed answer (confidence 1.0) is never overwritten by a lower-confidence
  extraction.
- Eval scoring: exact match after normalising case, spaces and number formatting; free-text
  fields (`remedy_wanted`, `defect_description`, …) pass when every expected word appears.
- `evals.run --llm oracle` answers with the expected values. It only proves the harness works;
  it is not a quality score.

## Classification and drafting (task 2.1)
- The user's own country/region choice always beats the classifier. A region that doesn't belong
  to the country, or any non-ISO value, is dropped. Case type `other` falls back to
  `refund_refused` (its generic ladder fits most disputes); the model's raw answer is logged.
- `classify` never changes `case.language`: that is the **draft** language the user picks
  (default `en`). The language the complaint was written in is logged in the `classified` event.
- **Money in letters is ISO code + locale-formatted number** (`PKR 45,000.00`,
  `INR 45,00,000.00`, `4.500.000,00 EUR`): symbols like `$` or `Rs` are ambiguous. The locale is
  `<language>_<country>` when Babel knows it, otherwise the language alone.
- Drafting: the template is rendered first (facts only), then the smart model polishes it. If the
  model fails to return valid JSON after retries, the plain filled template is used. The
  disclaimer is appended by code, never left to the model.
- A new draft for a step marks older open drafts of that step `superseded`.

## Fact check and approval (task 2.2)
- Code check allow-list = case facts + the trusted template rendering (facts, today, reply-by
  date) + text already approved in the case. Numbers are compared after normalising commas,
  spaces, European decimals and trailing `.00`; dates in ISO, `D/M/YYYY`, `4 November 2026` and
  `November 4, 2026` forms are compared as dates; IDs are letter+digit tokens with hyphens.
- The model check runs only when the code check passes. If the model can't produce valid JSON it
  returns no issues (the code check already ran), so a confused small model cannot block forever.
- **The user's own edits must also pass the code check** at approval (`UnsupportedFacts`).
  `PUT /messages/{id}` (edit only) saves the edit and returns warnings without blocking; approval
  then enforces it. To use a new value, the user adds it as a fact first.
- Approve/reject live in `escalate/agent/approval.py`; a test asserts no other module assigns
  `approved_at`.

## Channels (task 2.3)
- `escalate.channels.send_message()` is the single place that records a send (`sent_at`,
  status `sent`, `message_sent` event). It is idempotent and calls `require_approval()` before
  touching a channel; every channel's own `send()` calls it again.
- **post / court / web_form** return `delivered=False` and log `awaiting_user_delivery`. They
  become `sent` via `confirm_delivery()`; post and court require an uploaded proof (Evidence of
  the same case). **info** steps (guides for the user) are marked sent on approval.
- Printable letters are generated on demand as PDF bytes (not stored on disk unencrypted).
- Gmail API token is stored Fernet-encrypted at `secrets/gmail_token.enc` (single-user v0.1).
- Email recipients must look like an email address; otherwise sending fails before any network
  call (e.g. a WhatsApp number in `seller_contact`).

## Scheduler and replies (task 2.4)
- Job defaults: `coalesce=True`, `misfire_grace_time=None` (a wake-up missed while the machine
  was off still fires on the next start), timezone UTC.
- Tests drive a thread-less `ManualScheduler` (real job store and triggers, `DebugExecutor`)
  under freezegun instead of sleeping or racing a background thread.
- **Code-side rule in the reply judge:** a promise with no date is `refused` even if the model
  says `resolved`/`partial`. An empty reply (timer fired) is `no_reply` without a model call.
- `pick_next` skips steps whose `when` fails by following their `on_no_reply` edge; `partial`
  uses `on_partial`, falling back to `on_refused`.
- Deadline warnings are logged once per deadline per day (`deadline_warning` events), from
  10 days left (playbook `warn_when_days_left`) and after the deadline has passed.

## Graph and runner (task 2.5)
- **Graph changes vs. the section 7 skeleton** (same nodes, a few extra edges):
  - `intake` classifies first when the case has no type yet, because extraction needs the
    playbook's fact list. `classify` then re-resolves the playbook with the extracted company
    name (no extra model call) and never switches playbooks mid-ladder.
  - `draft -> ask_missing` when a step needs facts the case doesn't have (e.g. the seller's
    postal address for the legal notice); answers loop back through `intake` (no re-extraction).
  - `send` pauses with `interrupt({"type": "confirm_delivery"})` for post/court/web-form steps,
    and ends the graph after a final step with no `wait_days`.
  - Scam cases route to `urgent_checklist` only once (`checklist_done`).
  - Routing uses `state["case_type"]` rather than `facts["case_type"]`.
- **Fact-check loop is bounded**: after 3 failed attempts the plain facts-only template is
  used (and the model check is skipped for it), so a small model can never loop forever.
- The runner does the DB action (approve/reject/edit, record reply, confirm delivery) in its own
  committed transaction **before** resuming the graph. Resuming with "approve" without
  `approve_message` fails at `send` (test proves it).
- Logging a reply cancels the pending wake-up; a stale wake-up for another step is ignored.
- A process-wide lock serialises graph runs (the scheduler thread and API can't interleave).
- A failed node (e.g. SMTP down) can be re-run with `runner.retry(case_id)`.

## API and UI (task 2.6)
- Extra endpoints beyond section 10's 12: `POST /cases/{id}/start` (so evidence can be uploaded
  before the agent reads the case; `POST /cases` also accepts `start: true`),
  `POST /cases/{id}/checklist/ack`, `POST /cases/{id}/retry`,
  `POST /messages/{id}/confirm-delivery`, `GET /messages/{id}/printable.pdf`, `GET /health`,
  `GET /checklist`, `POST /settings/llm-test`.
- **Every approval re-runs the code fact check** on the final text, against the facts and the
  fact-checked draft (`Message.original_body`, new column + migration). So an edit saved with
  `PUT /messages/{id}` can't slip an invented amount past approval.
- On startup the API runs `alembic upgrade head`, compiles the graph and starts the scheduler
  with the daily 09:00 UTC deadline scan.
- Error mapping: wrong state 409, unsupported facts 422 (with `issues`), missing model or
  unreachable LLM 503, PDF libs missing 503.
- The UI reads the privacy banner from `GET /health` (`is_cloud`) so it stays API-only.

## Pakistan pack (task 3.1)
- Templates never name a specific Act, section or court address. They say "the applicable
  provincial Consumer Protection Act" and "District Consumer Court" (as in the section 6 spec);
  a `TODO(verify …)` block in the playbook lists what a lawyer must confirm.
- Optional fact `court_name` overrides "DISTRICT CONSUMER COURT" in the court documents.
- Late filing: `pick_next` computes `late` from the deadline tracker; the court step then
  appends `adds_if_late` (condonation application) after a `---` separator.
- **A missing `en/` template is now a validator error** (English is the fallback for every
  draft language), not just a warning.
- The fact check converts all Unicode decimal digits (Urdu, Devanagari, …) to ASCII first, so
  an invented amount in another script is still caught.
- The disclaimer gains an Urdu line for Urdu drafts; the English line always stays.

## Subscription and scam flows (task 3.2)
- **Scam cases show the urgent checklist immediately after classification, before fact
  extraction, questions or any letter**: `intake` returns early for an unacknowledged scam, and
  `urgent_checklist -> intake` continues the normal flow afterwards.
- Checklists live in `playbooks/<cc>/scam_checklist.yaml` with fallback to
  `playbooks/intl/generic/scam_checklist.yaml`; they always carry the "we never ask for
  passwords/PINs/OTPs" and "recovery scammer" warnings. The UI has a "do this now" page that
  works before any case exists.
- The validator rejects playbook facts that look like secrets (`password`, `pin`, `otp`, `cvv`,
  …). Only `card_last4` is used for cards; never the full number.
- Scam ladder: bank/card-issuer fraud report (email, 10 days) -> police report (post) ->
  national fraud-reporting body (web form). Subscription ladder: cancel request (7 days) ->
  final notice listing charges (14) -> card-issuer dispute (30) -> consumer authority.

## India, UK, US packs (task 3.3)
- Each pack is country-wide (`playbooks/<cc>/general/refund_refused.yaml`) and reuses the
  generic written-demand template for step 1, with its own template for the distinctive later
  steps (IN legal notice + Consumer Commission complaint; GB letter before action + small-claim
  guide; US final demand + state attorney general complaint + small-claims guide).
- Named only institutions and laws I am certain exist (Consumer Protection Act 2019 and the
  District Consumer Disputes Redressal Commission in India; Consumer Rights Act 2015, Citizens
  Advice, Action Fraud, Police Scotland in the UK; FTC and FBI IC3 in the US). **No URLs, phone
  numbers or section numbers**; a test fails if one appears. The PK scam checklist does not name
  the cybercrime agency (it changed recently and I could not verify the current name).
- India's filing deadline (730 days) is marked `TODO verify` in its rule text and warns at 30
  days left. GB and US set no deadline (it varies by nation/state).
- The validator now also checks scam checklists (load, have items, keep both safety warnings).

## Localisation (task 3.4)
- UI strings live in `locales/<lang>.json`, loaded by `ui/i18n.py`; `t("key", **values)` falls
  back to English, then to the key itself. A test fails if the app uses a key that `en.json`
  lacks, or if a translation's `{placeholders}` differ from English.
- `locales/ur.json` holds only the strings I'm confident of (the brief allowed "keys only where
  unsure"); everything else falls back to English. Urdu switches the page to right-to-left.
- Pages are tracked by stable ids (`new_case`, `dashboard`, …), so switching language keeps the
  current page.
- `locale_for()` only uses `<lang>_<CC>` when CLDR really has that locale (Babel otherwise
  accepts e.g. `en_ZZ`).
- Drafts already use `case.language` (templates per language, falling back to `en/` with the
  model asked to write in the case language).

## Case PDF and full UI (task 3.5)
- The case file is built from `escalate/export/case.html.j2` (autoescaped, so user text can't
  inject HTML) and rendered with WeasyPrint. `build_case_html()` is tested locally;
  the real PDF test (text extracted with pypdf must contain the case number and every event
  date) runs where Pango is installed (CI, Docker).
- Pages: cover (parties, amount, status, playbook), facts with source evidence and confidence,
  dated timeline (only whitelisted payload fields, never free text), sent/received/approved
  messages in full, evidence with JPEG thumbnails (decrypted in memory) and SHA-256. The
  disclaimer appears on the cover and at the end.
- `pytesseract`/`pypdf`/`PIL` are now imported at module level in `escalate/evidence/ocr.py`:
  importing pandas (a pytesseract dependency) for the first time while freezegun is active
  crashes the interpreter. Tests also tell freezegun to ignore pandas.
- New screens: Questions, Log a reply (shows the verdict), My cases (status filter), Settings
  (LLM test button, email mode, default draft language). The dashboard adds PDF download and
  withdraw. Settings can't edit `.env` from the browser (by design); it explains what to set.
